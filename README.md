# 多重課題シミュレーション

医療者向けの多重課題トレーニングゲームです。次々に入る呼び出しに優先順位をつけ、中断・委任・安全確認を判断しながら点数を競います。
GitHub Pages（静的ホスティング）と Firebase（認証・データベース）で動きます。サーバーの用意は不要です。

## できること

- **4言語**：日本語・英語・韓国語・中国語。画面右上で切り替えます。シナリオ文も4言語で持っています。
- **7職種**：医師・看護師・薬剤師・理学療法士・作業療法士・管理栄養士・臨床検査技師。既定シナリオは10本で、管理画面から追加できます。
- **経験レベル**：学生／1年目／2〜3年目／4年目以上。レベルが上がるほど課題数が増え、呼び出しが早くなり、期限が短くなります。得点にはレベル係数（×1.0〜1.3）がかかります。
- **ひとりで練習**：NPC 3人との個人戦、または NPC チームとの対抗戦。
- **オンライン対戦**：セッションコード・参加リンク・QRコードで、別々の端末から同じセッションに参加できます。職種・経験が混在していても、各自が自分の職種のシナリオを解いて点数を競います。
- **個人戦と対抗戦**：対抗戦はチーム平均点で順位をつけます（人数差があっても公平になるように）。合計点も表示します。
- **Googleログイン**：参加者は Google アカウントでログインします。
- **管理者**：メール/パスワードまたは Google アカウントでログインし、シナリオ編集・動画登録・プレイログ閲覧・監査ログ閲覧・CSV書き出しができます。
- **初期パスワード変更の記録**：初期パスワードのままでは管理機能が使えず、変更すると日時・アカウントが監査ログに記録されます。以後の変更もすべて記録されます。
- **動画の登録**：YouTube・Vimeo・Googleドライブのリンク、または mp4 等の URL をシナリオごとに登録できます。Firestore に保存されるので、アプリを開き直しても残ります（任意で動画ファイルのアップロードも可）。

## ファイル構成

```
index.html            画面の入れ物
style.css             デザイン
js/app.js             画面・Firebase連携・管理機能
js/engine.js          ゲームロジック（得点計算）
js/data.js            職種・レベル・安全確認・既定シナリオ（4言語）
js/i18n.js            画面の文言（4言語）
js/firebase-config.js Firebase の設定値（要編集）
firestore.rules       Firestore セキュリティルール
storage.rules         Storage ルール（動画アップロードを使う場合のみ）
```

## セットアップ（15分ほど）

### 1. Firebase プロジェクトを作る
1. https://console.firebase.google.com でプロジェクトを作成します（無料の Spark プランで動きます）。
2. 「プロジェクトの設定」→「マイアプリ」→ ウェブアプリ（`</>`）を追加します。
3. 表示された設定値を `js/firebase-config.js` に貼り付けます。

### 2. ログイン方法を有効にする
1. 「Authentication」→「ログイン方法」で **Google** と **メール / パスワード** を有効にします。
2. 「Authentication」→「設定」→「承認済みドメイン」に `あなたのユーザー名.github.io` を追加します。

### 3. Firestore を作る
1. 「Firestore Database」→ データベースを作成します（本番モード、ロケーションは `asia-northeast1` 推奨）。
2. 「ルール」タブに `firestore.rules` の内容を貼り付けて公開します。

### 4. 管理者を登録する
**メール/パスワードの管理者（初期パスワード方式）**
1. 「Authentication」→「ユーザー」→「ユーザーを追加」で、メールアドレスと初期パスワードを登録します。
2. 作成されたユーザーの **UID** をコピーします。
3. Firestore で `admins` コレクションを作り、ドキュメントID を UID にして、次のフィールドを追加します。
   - `mustChangePassword`（boolean）: `true`
   - `name`（string）: 任意の名前
4. アプリの「管理者」から初期パスワードでログインすると、パスワード変更画面が表示されます。変更すると監査ログに「初期パスワード変更」が記録され、管理機能が使えるようになります。

**Google アカウントの管理者**
1. アプリの「管理者」画面で Google ログインします。管理者未登録の場合は UID が表示されます。
2. その UID をドキュメントIDにして `admins` コレクションに登録します（`mustChangePassword` は不要）。

### 5. GitHub Pages で公開する
1. このフォルダの中身をリポジトリのルートに置いて push します。
2. リポジトリの「Settings」→「Pages」で、ブランチ `main`、フォルダ `/ (root)` を選びます。
3. 数分後に `https://あなたのユーザー名.github.io/リポジトリ名/` で開けます。

### （任意）動画ファイルのアップロード
リンク登録だけなら不要です。ファイルを直接アップロードする場合は、Firebase を Blaze（従量課金）プランにして Storage を有効化し、`storage.rules` を設定し、`js/firebase-config.js` の `STORAGE_ENABLED` を `true` にします。

### ローカルで確認するとき
ES モジュールを使っているため、ファイルを直接開くのではなく簡易サーバーで開いてください。
```
python3 -m http.server 8000
# → http://localhost:8000
```
`firebase-config.js` が未設定のままでも「ひとりで練習」は動きます。ローカル確認時は Firebase の承認済みドメインに `localhost` が入っていることを確認してください（既定で入っています）。

## 遊び方

1. ホームで表示名・職種・経験を選びます。
2. **ひとりで練習**：形式とシナリオを選んで開始します。
3. **みんなで対戦**：主催者が「セッションを作る」→ コード・リンク・QRを共有 → 参加者が参加 → 主催者が形式（個人戦／対抗戦）を選んで開始します。対抗戦では各自がチームA/Bを選びます。
4. 呼び出しごとに「対応する」か「任せる」を選びます。対応中に別の課題へ移ると、元の課題は中断されます。移る前に「再開メモを残す」を押しておくと、再開時の失点を防げます。
5. 安全確認が必要な課題では、着手時に確認問題が出ます。

## 得点の考え方（文献との対応）

| 評価軸 | 加点・減点 | 根拠 |
|---|---|---|
| 優先順位 | 最も優先度の高い課題に着手＋8、より低い課題を先に選ぶと減点 | 生命→安全→苦痛→その他（国内の新人看護師多重課題研修の枠組み） |
| 時間 | 期限内の完了で最大＋20、期限切れは優先度に応じて減点（生命に関わる課題は安全軸でも減点） | 中断による遅延・見落とし |
| 安全確認 | 正解＋8、誤り−10 | 患者確認・6R・SBAR・検体ラベル・パニック値報告 |
| 中断からの再開 | メモありで再開＋4、メモなし−6 | 予定記憶（Dodhia & Dismukes 2009）、interruption lag での再開準備（Trafton ら 2003） |
| 委任・報告 | 適切な委任＋6、自分の判断が要る課題を任せようとすると−8 | 委任の判断、中断管理 |

最終スコアは「獲得点 ÷ 満点 × 1000 × レベル係数」です。職種ごとにシナリオの課題数が違っても比べられるように、1000点満点に換算しています。

## 管理画面

- **シナリオ**：既定シナリオの編集（「既定に戻す」で元に戻せます）、新規追加、プレイ候補からの除外。課題は JSON で編集します（書き方は画面内の説明を参照）。
- **動画**：シナリオごとに動画 URL を登録・プレビュー・削除します。
- **プレイログ**：全プレイの得点・5軸・行動統計を表示し、CSV（Excel 対応）で書き出せます。研究用の行動ログ（イベント列）も Firestore に保存されています。
- **監査ログ**：管理者ログイン、パスワード変更、シナリオ・動画の変更を記録します。ログは追記のみで、改ざん・削除はできません。
- **パスワード**：メール/パスワード管理者のパスワード変更。

## データ構造（Firestore）

| コレクション | 内容 | 権限 |
|---|---|---|
| `admins/{uid}` | 管理者登録、`mustChangePassword` | コンソールで作成、本人はフラグのみ更新 |
| `scenarios/{id}` | 追加・編集したシナリオ | 誰でも閲覧、管理者のみ書き込み |
| `scenarioMeta/{id}` | 動画 URL | 誰でも閲覧、管理者のみ書き込み |
| `sessions/{code}` / `players/{uid}` | 対戦セッションと参加者の得点 | ログイン者が閲覧、主催者・本人が更新 |
| `logs` | プレイログ | 本人が追記、管理者のみ閲覧 |
| `auditLogs` | 監査ログ | 本人が追記、管理者のみ閲覧 |

## 注意と限界

- 理学療法士・作業療法士・管理栄養士・臨床検査技師のシナリオは、職種固有の研究が少ないため近接領域（検査医学、核医学技師、栄養士の時間動作研究など）の知見をもとに作成しています。現場の専門家による監修を推奨します。
- 対戦中は各自の得点を5秒ごとに送信し、全員の画面に反映します。このため読み取り回数はおよそ「参加人数² × 30回」になります（30人なら1セッション約2.7万回）。無料の Spark プランの上限は読み取り1日5万回・書き込み1日2万回なので、大人数の授業を毎日行う場合は Blaze（従量課金）プランを検討してください。超過分の費用は少額です。
- 同じ端末のブラウザがバックグラウンドになると、ゲームの時間の進みが遅くなります。
